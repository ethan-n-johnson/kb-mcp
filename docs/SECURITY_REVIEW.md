- **FAIL**: checked and not acceptable (none open; see "Problems found and fixed").

## Problems found and fixed in this phase

1. **Rate limit could be bypassed (phase 10 Dockerfile).** The image ran uvicorn with `--proxy-headers --forwarded-allow-ips '*'`. With `*`, uvicorn takes the left-most `X-Forwarded-For` entry, which is whatever the caller sends (CloudFront appends the viewer address after it). A client rotating that header would never hit a per-address limit, and the audit and logs would show forged addresses. Fixed: uvicorn's proxy handling is off (`--no-proxy-headers`), and `kb/clientip.py` reads the address from the right of the header, `KB_PROXY_HOPS` entries in (2 behind CloudFront and the ALB, set in the user data). Tests: `test_security.py::test_clients_have_separate_budgets_and_the_left_most_entry_cannot_be_forged` and the `client_address_is_counted_from_the_right` cases. Laptop check below.
2. **Swagger UI would break under the CSP.** FastAPI served `/docs` and `/redoc`, which load scripts from a CDN, and `script-src 'self'` blocks them. Both are now off (`/openapi.json` stays). Test: `test_swagger_ui_is_off_because_it_needs_a_cdn_script`.
3. **Note, not changed:** a form post to a `/ui/...` write route with invalid fields and no token answers 422 before 401, because FastAPI validates form fields before the handler checks the token. Nothing is written either way. A request with valid fields and no token gets 401 (`test_every_non_get_route_refuses_a_missing_or_wrong_token`).

## Known limitations

1. **CloudFront to ALB is plain HTTP.** Viewers use HTTPS; the hop inside AWS is not encrypted (no custom domain or certificate in the sandbox). The Chrome extension therefore refuses the ALB URL and only accepts the CloudFront one.
2. **Bearer tokens instead of MCP OAuth 2.1.** Shared secrets, no per-user identity beyond the token name, no expiry. OAuth is the named future upgrade.
3. **The UI keeps the token in `sessionStorage`.** Any script running on the page could read it. The CSP (no inline script, same-origin scripts only), nh3 sanitizing and escaped templates are the controls; the token is cleared when the tab closes.
4. **Reads are public.** Search, `get`, tags, stale, gaps and `GET /api/audit` need no token, and the audit log shows token names and verify notes. Anyone who can reach the CloudFront URL can read the whole knowledge base.
5. **The CloudFront prefix list admits every CloudFront distribution**, not only ours, so someone with their own distribution could reach the ALB. The rate limit still counts the address CloudFront appended, but there is no origin secret header. A custom header with a secret value, checked by the app, would close this.
6. **SSRF guard and DNS rebinding.** `check_url` resolves a host and the HTTP client resolves it again; an attacker-controlled DNS server could answer differently the second time. The IMDS hop limit is 2 so the container can use the instance role, which makes the guard the only barrier to the metadata service.
7. **The instance role is broad** (AWS Academy gives no custom IAM). `EMR_EC2_DefaultRole` allows all of S3 in the account, CloudWatch, and several other services the app never uses (deviation 8).
8. **No limit on failed token guesses.** Only search is rate limited. Tokens are 32 random bytes when generated as documented, which is not guessable, but a short token would be.
9. **Tokens are cached for the life of the process** (`kb/config.py`), so editing the tokens object does not revoke a token until the container restarts.
10. **Unauthenticated requests are read up to 20 MB** before the token is checked (FastAPI parses the body first). The limit bounds the cost; it does not remove it. The cap is on the HTTP body, so a PDF sent as base64 JSON must be under about 15 MB.
11. **The rate limit lives in process memory** (one worker by design): it resets on restart, and visitors behind one NAT share a budget.
12. **Remote images in stored Markdown load.** `img-src` allows `https:` so documents can show diagrams, which lets an uploaded document make a viewer's browser contact another host.
13. **Resource use by parsers.** A 20 MB PDF of 300 pages or a very large HTML page still costs CPU and memory in the single process.
14. **The recovery point is a few seconds, not zero.** The database lives on the instance disk and reaches S3 as a snapshot at most every `KB_SNAPSHOT_INTERVAL` seconds (default 5) after a write. A hard kill with no SIGTERM loses the writes of the last interval; a graceful stop flushes a final snapshot. A bad delete reaches the snapshot within seconds too, so recovering from one uses a nightly backup or an earlier version of the snapshot (the bucket is versioned).
15. **The root volume may be unencrypted.** KMS is list only in the sandbox; if an encrypted root volume could not be launched, the fallback `Encrypted: false` leaves the live database unencrypted on the instance disk. Every copy in S3 stays encrypted. Record the outcome in `docs/PROGRESS.md`.
16. **The image tarball, every snapshot and the write tokens are readable with the instance role.** The role can read the whole bucket (limitation 7), so anything that reaches the instance credentials reads the knowledge base from S3. The SSRF guard (limitation 6) is the barrier.
17. **The write tokens are protected by the bucket, not by SSM.** They sit in `config/write-tokens` in the private, `AES256`-encrypted bucket (Block Public Access on, versioning keeps 30 days of old versions), because the sandbox instance role cannot read SSM Parameter Store (deviation 8). Anyone with S3 read on the bucket reads the tokens; in the sandbox that is the lab user and the instance role. Rotating a token means writing a new object and restarting the container.
18. **Container logs stay on the instance.** The instance role cannot write CloudWatch Logs, so logs survive only as long as the instance (and a failed boot copies them to `debug/` in the bucket). There is no central log search for an incident after an instance is replaced.
